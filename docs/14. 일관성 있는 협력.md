#### 객체 지향 설계의 목표

적절한 책임을 수행하는 객체들의 협력을 기반을 ㅗ결합도가 낮고 재사용 가능한 코드 구조를 창조 하는 것

#### 대부분 사람들은 유사한 요구사항을 구현하는 코드는 유사한 방식으로 구현 될 것이라고 예상

⇒ 유사한 기능은 서로 다른 방식으로 구현해서는 안됨

#### 설계경험이 풍부 → 어떤 위치 일관성 보장, 일관성 보장을 위한 방법이 직관적으로 결정

#### 일관성 있는 설계를 위해 일반적인 방법 → 디자인 패턴 학습하고 변경이라는 문맥안에서 적용

- 변하는 개념을 변하지 않는 개념으로부터 분리
- 변하는 개념을 캡슐화

⇒ 클래스는 명확히 단하나의 이유에 의해서만 변경돼야 한다.

#### 데이터 은닉 - 외부에 공객된 메서드를 통해서만 객체 내부 접근

- 클래스의 모든 인스턴스 변수는 private으로 선언 하고 오직 클래스의 메서드만이 인스턴스 변수 접근

#### 캡슐화 → 데이터 은닉 이상 ⇒ 소프트웨어에서 변할 수 있는 모든 개념을 감추는 것

- 객체의 퍼블릭 인터페이스와 구현을 분리 하는 것
- 코드 수정으로 인한 파급효과를 제어할 수 있는 모든 기법이 캡슐화의 일종

#### 객체 캡슐화

1. 변하는 부분을 분리해서 타입 계층을 만듬
2. 변하지 않는 부분의 일부로 타입 계층을 합성

#### 협력 패턴에서 추상화만으로 구성한 협력은 추상화를 구체적인 사례로 대체 함으로써 다양한 상황으로 확장 가능하게 해준다.

유사한 기능에 대해 유사한 협력 패턴을 적용하는 것은 객체 지향 시스템에서 개념적 무결성을 유지할 수 있는 효과 적인 방법

시스템이 일관성 있는 몇 개의 협력 패턴으로 구성된다면 시스템을 이해하고 수정하고 확장하는데 필요한 노력의 시간 아끼기 가능

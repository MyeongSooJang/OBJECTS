#### 객체 지향 설계 - 올바른 객체에게 올바른 책임을 할당하면서 낮은 결합도와 높은 응집도

- 객체의 상태가 아니라 행동에 초점을 맞추는 것
- 응집도가 높을 수록 변경의 대상과 범위가 명확하게 파악이 가능
- 캡슐화의 정도가 객체의 응집도와 결합도를 결정

#### 두가지 방법으로 시스템을 객체로 분할 가능

1. 상태
2. 책임

#### 변경될 가능성이 높은 부분 → 구현

#### 상대적으로 안정적인 부분을 → 인터페이스

#### 캡슐화 지키기

- 속성의 가시성을 private으로 설정했다고 해도 접근자와 수정자를 통해 속성을 외부로 제공한다면 캡슐화 깨진것
- 자신의 상태를 스스로 관리하는 자율적인 객체를 지향
- 변할 수 있는 것이라도 감추는것

#### 데이터 주도 설계 문제

- 처음부터 데이터에 관해 결정하도록 강요하여 너무 이른 시기 내부 구현에 초점을 맞춤
- 데이터 처리하는 작업과 데이터를 같은 객체 안에 두더라도 데이터에 초점이 맞춰지면 만족스러운 캡슐화가 힘듬

#### 객체지향 설계의 무게 중심은 항상 객체 내부가 아니라 외부에 맞춰져 있어야함

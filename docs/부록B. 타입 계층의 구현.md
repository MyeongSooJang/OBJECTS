#### 타입은 개념의 분류를 의미 / 클래스는 타입을 구현하는 한 가지 방법

- 타입 계층은 행동 호환성을 전제로, 이 장에서 타입 계층을 구현하는 방법인 동시에 다형성을 구현하는 방법 중 하나
- 올바른 타입 계층이 되기 위해서는 서브타입이 슈퍼 타입을 대체할 수 있도록 리스코프 치환 원칙을 준수

#### 타입은 객체의 퍼블릭 인터페이스를 가르킨다 → 클래스는 객체의 타입과 구현을 동시 정의

#### 상속으로 인한 결합 문제를 피하고 다중 상속이라는 구현 제약도 해결 할 수 있는 방법은 클래스 X

→ 인터페이스

580P 예시로 보고 알 수 있는 점

- 여러 클래스가 동일한 타입을 구현 가능
- 하나의 클래스가 여러 타입을 구현할 수 있음

#### 모든 구체 클래스의 부모 클래스를 항상 추상 클래스로 만들기 위해 노력하는 것

인터페이스를 이용해 타입을 정의하고 특정 상속 계층에 국한 된 코드를 공유할 필요가 있을 경우,

추상 클래스를 이용해 코드 중복을 방지 → 골격 구현 추상 클래스

#### 추상클래스만 사용했을때보다 인터페이스를 같이 사용했을때 장점

- 다양한 구현 방법이 필요할 경우 새로운 추상 클래스를 추가해서 쉽게 해결
- 부모 클래스가 존재하는 클래스라고 하더라도 인터페이스를 추가함으로써 새로운 타입 쉽게 확장

#### 덕타이핑 → 어떤 대상의 행동이 ‘무엇’과 같다면 그것을 ‘무엇’이라는 타입으로 취급

- 동적 언어에서 사용하는 방법
- 자바 같은 정적 언어에서는 두클래스를 동일한 타입으로 취급하기 위해서는 코드 상의 타입이 동일하게 선언되어야 함

⇒ 컴파일 시점에 발견할 수 있는 오류를 실행 시점으로 미룸 → 유연성 얻는 대신 코드의 안전성을 약화

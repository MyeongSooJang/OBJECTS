#### 전통적인 패러다임에서 코드를 재사용 → 코드를 복사한 후 수정

#### 💬 객체지향 → 재사용하기 위해 새로운 코드를 추가

- 상속
- 클래스의 인스턴스를 포함 → 합성

#### 중복 코드의 경우 변경을 방해 → 개별적으로 테스트해서 동일한 결과 확인 필요

- 판단 → 요구사항이 변경 되었을때 두코드가 수정 ⇒ 중복
- DRY(Don’t Repeat Yourself) 원칙 따르기

### 상속을 염두해 두고 설계되지 않는 클래스를 상속을 이용해 재사용 힘듬

- 재사용을 위해 상속 계층 사이에 무수히 많은 가정을 세워야 함
- 가정들의 이해가 안되면 코드 자체가 이해 안되는 상황이 발생

#### 코드 중복을 제거하기 위한 상속 사용이 원칙

1. 두 메서드 유사시 → 차이점을 메서드 추출
2. 자식 클래스의 코드를 상위로 올리기
    - 각 클래스는 서로 다른 변경 이유

#### 재사용을 위한 상속 문제

- 너무 강하게 결합 → super 참조를 이용하게 되면 두클래스는 강하게 결합
- 부모의 변경에 의해 자식 클래스가 영향 → 취약한 기반 클래스 문제(캡슐화 약화 / 결합도 상승)
- 불필요한 상속 문제 (Properties, Stack 사례) ⇒ 내부구조에 대한 규칙 깨트릴 위험
    - 인터페이스 설계는 제대로 쉽게, 엉터리로 쓰기에는 어렵게 하는 만들어야 함
- 오버라이딩 할 경우 부모 클래스가 자신의 메서드를 사용하는 방법에 자식 클래스 결합

#### 인스턴스 변수 변하지 않는 상황, 행동만 변경되면 상속 계층에 속한 각 클래스들 독립적 진화

#### 📌 인스턴스 변수 추가 시

→ 자식 클래스는 인스턴스를 생성할때 부모 클래스에 정의된 인스턴스 초기화 필요 → 영향이 발생

#### 객체 생성 로직은 유연하게 대응 할 수 있는 방법들이 여럿 존재 → 핵심 로직 중복 막기

#### 재사용 가능 코드 → 심각한 버그가 존재하지 않는 코드 → 노력과 테스트를 줄이기 가능

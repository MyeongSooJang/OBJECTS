### 상속의 두 가지 용도

1. 타입 계층(서브 타이핑) - 부모클래스는 일반적인 것을 구현(일반화) / 자식 클래스는 특수한 개념을 구현(특수화)
    - 자식 클래스와 부모 클래스 사이의 행동 호환성은 부모 클래스에 대한 자식 클래스의 대체 가능성
2. 코드 재사용(서브클래싱)  - 재사용만을 위해 사용할 경우, 부모와 자식 강하게 결합하여 변경 힘듬

⇒ 일차적인 목표는 객체의 행동을 기반으로 타입 계층을 구현하는 것이어야 한다.

#### 타입으로 분류 될때 그 대상을 인스턴스 → 객체

- 심볼 : 타입에 이름을 붙인것
- 내연 : 타입에 속하는 객체들이 공유하는 속성과 행동의 집합
- 외연 : 타입에 속하는 객체

#### 목적

1. 타입에 수행 될 수 있는 유효한 오퍼레이션의 집합을 정의
    - 객체의 타입에 따라 적용 가능한 연산자의 종류를 제한하는 것
2. 타입에 수행되는 오퍼레이션에 미리 약속된 문맥을 제공

⇒ 오퍼레이션의 종류와 의미를 정의함으로써 코드의 의미를 명확하게 전달하고 개발자 실수를 방지

개념 - 타입은 공통 적인 특징

프로그래밍 언어 - 타입이란 동일한 오퍼레이션을 적용

#### 객체가 수신할 수 있는 메시지 집합 → 퍼블릭 인터페이스 (객체 타입을 결정하는 것)

일반적인 타입 - 슈퍼 타입

특수한 타입 - 서브 타입

#### 타입을 구현하는 방법 → 클래스와 상속

#### 상속을 사용 해야하는 시점

- 상속 관계가 is-a 관계 → [자식 클래스] 는 [부모 클래스] 다 성립하는 경우
- 클라이언트 입장에서 부모 클래스의 타입으로 자식 클래스를 사용해도 무방한가

⇒ 행동이 호환될 경우에만 타입 계층으로 묶어야 한다 → 중요한 것은 클라이언트에 관점

- 두 타입이 동일 하게 행동할 것을 기대한다면 묶는게 가능

#### 설계가 반영할 도메인의 요구사항이고 그 안에서 클라이언트가 객체에게 요구하는 행동

- 자연어에 현혹되지 말고, 클라이언트가 기대하는 행동에 집중

#### 우리가 알고 있는 개념 중 상속이라고 생각했는데 아닌것 → 정사각형과 직사각형

- 부모 클라이언트에 대한 클라이언트의 가정을 준수해야 한다는 것을 강조

#### 리스코프 치환 원칙이 개방-폐쇄 원칙을 지원

- 자식 클래스가 클라이언트 관점에서 부모 클래스를 대체 할  수 있다면 기능확장을 위해 자식 클래스를 추가하더도 코드를 수정하지 않아도 된다.

#### 계약에 의한 설계

- 사전 조건 - 클라이언트가 정상적을 메서드를 실행하기 위해 만족시켜야하는 것
- 사후 조건 - 서버가 클라이언트에게 보장해야 하는 것
- 클래스 불변식 - 메서드 실행 전과 실행된 후에 인스턴스가 만족시켜야하는 것

#### 서브 타입 계약

- 서브 타입에 더 강력한 사전 조건 정의 불가능
- 서브 타입에 슈퍼타입과 같거나 더 약한 사전조건을 불가능

- 서브타입 슈퍼타입과 같거나 더 강한 사후조건 정의 가능

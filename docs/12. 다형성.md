#### 상속 - 클라이언트 관점에서 인스턴들을 동일하게 행동하는 그룹으로 묶기로 사용하도록

- 데이터 관점에서 상속은 자식 클래스의 인스턴스 안에 부모 클래스의 인스턴스를 포함
- 행동 관점에서는 부모 클래스의 모든 퍼블릭 메서드는 자식 클래스의 퍼블릭 인터페이스에 포함
    - 런타임 시스템 - 자식 없을 경우 부모 탐색
- 상속은 동적으로 메서드를 탐색하기 위해 현재의 실행 문맥을 가지고 있는 self 참조를 전달

#### 다형성

- 유니버셜 다형성
    - 매개변수 - 제네릭 프로그래밍과 관련 인스턴스 변수나 메서드의 매개변수 타입을 임의 타입으로 선언한 후 사용시점에 구체적인 타입
    - 포함(서브타입) - 메시지가 동일 하더라도 수신 객체의 타입에 따라 수행하는 행동
- 임시 다형성
    - 오버로딩
    - 강제 - 동일한 연산자를 다양한 타입에 사용할 수 있는 방식 (연산자 + )

#### 객체 지향 패러다임의 근간 - 데이터와 행동을 객체라고 불리는 하나의 실행 단위 안 통합

#### 부모 클래스와 자식 클래스에 동일한 시그니처를 가진 메서드가 존재할 경우 자식이 우위

- 메시지 처리를 못하면 부모 클래스에에게 위임
- 동일한 시그니처를 가지는 자식클래스의 메서드는 부모 클래스를 감춤
- 시그니처 동일하지 않은 메서드들은 상속 계층에 걸쳐 공존
    - 오버라이딩 - 메서드를 감춤
    - 오버로딩 - 공존
        - 상속 계층 사이에서 같은 이름을 가진 메서드를 정의하는 것도 오버로딩

#### 동적 메서드 탐색 - 부모 클래스 타입 전송되더라도 실제 클래스를 기반으로 실행된 메서드 선택

- 함수 호출 전통 언어 → 호출될 함수 컴파일 시점 ⇒ 정적 바인딩
- 객체 지향 언어 → 메시지를 수신했을 때 실행 될 메서드 런타임 시점 ⇒ 동적 바인딩, 지연바인딩

#### self 전송이 깊은 상속 계층과 계층 중간중간 함정처럼 숨겨져 있는 메서드 오버라이딩과 만나면 극단적으로 이해하기 어려운 코드 생성

#### 동적 언어 → 컴파일 시점 x → 실행 해보기 전까지 모름

- 동적 타입 언어 이해할 수 없는 메시지를 처리할 수 있는 능력을 가짐

  → 메시지가 선언된 인터페이스와 메서드 정의된 구현 분리

- 메시지 전송자 (원하는 메시지 전송) / 메시지 수신사 (스스로 판단에 따라 처리)

❌ 수정하기 어렵게 만들뿐만 아니라 디버깅 과정 어렵게 함 → 동적특성과 유연성으로 인한 단점

#### SUPER - 부모 클래스의 메서드가 아니라 더 상위 메서드 일 가능성 존재

#### SELF - 메시지 탐색 클래스 미정 / SUPER - 전송에서 미리 정해짐

#### 위임 - 자신이 수신한 메시지를 다른 객체에게 동일하게 전달에서 처리 요구

- 자신 정의 하지 않거나 처리할 수 없는 속성 또는 메서드의 탐색 과정을 다른 객체로 이동시키기 위해

#### 프로토 타입 기반 개게 지향 언어 (JavaScript)

- 인스턴스 메시지를 수신하면 먼저 메시지를 수신한 객체의 prototype 안에서 메시지에 응답할 적절한 메서드가 존재하는지 검사
- 메서드를 탐색하는 과정은 클래스 기반 언어의 상속과 거의 동일
- 클래스라는 개념이 존재하지 않기 때문에 메시지 위임으로 다형성을 구현

#### 클래스는 객체를 편리하게 정의하고 생성하기 위해 제공되는 프로그래밍 요소 일뿐

#### 중요한 것은 메시지와 협력

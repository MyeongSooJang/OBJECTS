### 상속 & 합성

- 상속 : 부모 클래스와 자식클래스 사이 의존성 → 컴파일 (is-a 관계), 정적인 관계
- 합성 : 두 객체 사이의 의존성 → 런타임 (has - a 관계), 동적인 관계

### 상속 문제

1. 불필요한 인터페이스 상속 → 부적합한 부모 클래스의 오퍼레이션이 상속
2. 메서드 오버라이딩 오작용 → 오버라이딩 할때 자식클래스가 부모 클래스의 메서드 호출 방법에 영향
3. 동시 수정 문제

#### 상속의 경우 일반적으로 this 참조는 동적 super 참조는 컴파일 시점

→ 상속에서는 부모 클래스와 자식 클래스 관계를 변경할 방법이 없음

#### 자바를 비롯한 대부분의 객체 지향 언어는 단일 상속만 지원

⇒ 상속으로 인해 발생하는 중복 코드 문제 해결이 힘듬

#### 상속을 남용

- 하나의 기능을 추가하기 위해 필요 이상으로 많은 수의 클래스를 추가 → 클래스 폭발 / 조합의 폭발

#### 현재 말한 단점들은 구현 상속에 국한 → 인터페이스를 통한 상속을 지향

#### 합성 → 퍼블릭 인터페이스에 의존

예) 합성으로 변경한 Properties는 Hashtable의 내부 구현에 알지 못함(349p)

추가적으로 불필요한 오퍼레이션들이 퍼블릭 인터페이스에 스며드는 것도 방지 가능

#### 포워딩

- 선택적으로 노출이 가능
- 내부를 자유롭게 교체 가능
- 결합도 낮추기 가능

#### 믹스인 → 코드 일부를 클래스 안에 섞어 사용

- 코드를 섞어 넣는다는 기본 개념을 구현하는 방법이 언어마다 다르기 때문에 어렵다고 느껴짐

믹스인되기 전까지 상속 계층 안에서 TaxablePolicy 트레이트 위치가 결정 되지 않음 → 384P

### 사용해도 클래스 폭발 문제?

- 클래스 폭발 문제는 클래스가 늘어난다는 것이 아니라 클래스가 늘어날수록 중복 코드도 증가하는 것
- 믹스인에서는 이런 것이 발생하지 않음

#### 믹스인은 결론적으로 슈퍼클래스로부터 상속될 클래스를 명시
